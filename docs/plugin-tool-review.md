# SourceNerve plugin tool review

This document is the submission-time review matrix for SourceNerve MCP tool metadata. The values below are generated by the policy model in `src/mcp_plugin.rs`, which decorates every MCP tool with `readOnlyHint`, `destructiveHint`, `idempotentHint`, and `openWorldHint`. The test suite also requires every current public tool to have an explicit policy instead of silently relying on the conservative fallback.

OpenAI submission requires accurate `readOnlyHint`, `openWorldHint`, and `destructiveHint` values for every MCP tool. SourceNerve treats a tool as non-read-only whenever it can persist SourceNerve state, even if the user-visible operation is primarily a lookup.

## Review notes

- Public OAuth users never receive `state_backup_create` or `state_backup_validate`; those remain operator-only.
- OAuth authorization is enforced separately from tool annotations. A write tool additionally requires `sourcenerve:write`, a matching server-side read-write `[[oauth.grant]]`, and a writable workspace.
- `task_get`, `task_git_review`, `task_github_pull_get`, and `task_provider_pull_get` are deliberately `readOnlyHint=false` because they may persist lifecycle observations even though their primary user-facing result is status/review information.
- Push and provider tools use `openWorldHint=true` because they can contact or modify an external repository host. Local source mutation uses `openWorldHint=false`.
- Merge and patch-application tools are `destructiveHint=true`. SourceNerve workflow instructions additionally require an explicit user request before merge and never treat a green CI observation alone as permission to merge.

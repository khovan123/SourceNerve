# SourceNerve Desktop Bootstrap Broker

Issue: #84

Architecture: `docs/desktop-architecture-adr.md`

Bootstrap profile: `docs/desktop-bootstrap-profile.md`

## Purpose

The Bootstrap Broker is the server-side trust boundary that lets SourceNerve Desktop reach a zero-touch state without distributing Cloudflare account credentials to end-user machines.

Desktop still performs interactive Auth0 login. After login, the Desktop uses its SourceNerve OAuth access token to enroll an installation. The broker validates the same SourceNerve OAuth token, owns the Cloudflare account-level API credential, creates/reuses the installation routing assignment, and returns only the tunnel run credential required by that installation.

The local SourceNerve bearer remains a separate per-install secret generated by Desktop; the broker does not create or persist it.

## Runtime model

```text
Desktop
  |
  | Auth0 access token + installationId
  v
SourceNerve Bootstrap Broker
  |  validates SourceNerve OAuth JWT
  |  owns Cloudflare account API credential
  |
  +--> create remotely managed tunnel
  +--> configure hostname -> http://127.0.0.1:7331
  +--> create proxied DNS CNAME
  +--> obtain tunnel run token
  |
  v
Desktop secure store
  |
  v
bundled cloudflared
```

The account-level Cloudflare credential never appears in the enrollment response, renderer, Desktop product profile, repository, or state database.

## Routes

The broker is optional and is mounted only when `SOURCENERVE_DESKTOP_BROKER_ENABLED=true` and SourceNerve OAuth is configured.

### `POST /v1/desktop/enroll`

Authorization: SourceNerve OAuth bearer token.

Request:

```json
{
  "installationId": "install_01JABCDEF1234567890",
  "clientVersion": "0.1.0",
  "platform": "linux",
  "arch": "x86_64"
}
```

Behavior:

- validates token using the existing SourceNerve OAuth runtime;
- derives the authenticated Auth0 subject from that already-verified JWT;
- validates/bounds installation and client metadata;
- rate-limits enrollment mutations;
- reuses an existing active assignment for the same subject + installation ID;
- rejects a revoked assignment;
- creates a deterministic opaque hostname for a new assignment;
- creates/configures a remotely managed Cloudflare tunnel;
- creates a proxied DNS CNAME to `<tunnel-id>.cfargotunnel.com`;
- persists only assignment identifiers and status;
- returns the installation-scoped tunnel run credential.

Response shape:

```json
{
  "installationId": "install_01JABCDEF1234567890",
  "hostname": "<opaque>.fogewise.io.vn",
  "tunnelId": "<cloudflare-tunnel-id>",
  "tunnelToken": "<installation-scoped-run-credential>",
  "status": "active"
}
```

The `tunnelToken` must be consumed by Electron Main and written directly to OS secure storage. Renderer must receive only safe status and hostname metadata.

### `GET /v1/desktop/bootstrap-status?installationId=...`

Returns persisted assignment status for the authenticated owner. It never returns the tunnel token.

### `POST /v1/desktop/tunnel/rotate`

Request:

```json
{
  "installationId": "install_01JABCDEF1234567890"
}
```

The broker generates a fresh 32-byte tunnel secret from the operating system random source, rotates the Cloudflare tunnel secret, obtains the new tunnel token, and asks Cloudflare to disconnect old tunnel connections. The response contains the new run credential so Electron Main can replace the secure-store entry atomically.

### `POST /v1/desktop/revoke`

Deletes the persisted assignment's DNS route and tunnel and marks the local assignment record revoked. Calling revoke again is idempotent from the Desktop user's perspective.

## Persistent state

Migration `0016_desktop_installations.sql` adds `desktop_installations`.

Stored:

- installation ID;
- Auth0 subject;
- Cloudflare tunnel ID;
- Cloudflare DNS record ID;
- opaque hostname;
- active/revoked status and timestamps.

Not stored:

- Cloudflare account API token;
- Cloudflare tunnel run token;
- Auth0 access/refresh token;
- local SourceNerve bearer;
- Git provider credentials.

Re-enrollment of an active installation asks Cloudflare for the current run token instead of storing it in SQLite.

## Server environment

The broker is disabled by default.

Required only on the server/operator deployment that owns Cloudflare provisioning:

```text
SOURCENERVE_DESKTOP_BROKER_ENABLED=true
SOURCENERVE_CLOUDFLARE_ACCOUNT_ID=<account id>
SOURCENERVE_CLOUDFLARE_ZONE_ID=<zone id>
SOURCENERVE_CLOUDFLARE_API_TOKEN=<server-only scoped token>
SOURCENERVE_DESKTOP_HOSTNAME_SUFFIX=fogewise.io.vn
```

The broker prepends one opaque installation label to `SOURCENERVE_DESKTOP_HOSTNAME_SUFFIX`. When the zone relies on Cloudflare Universal SSL for `*.fogewise.io.vn`, use the zone apex (`fogewise.io.vn`) so generated installation hosts remain one label below the apex and are covered by that certificate. A deeper suffix such as `mcp.sourcenerve.fogewise.io.vn` would produce `<opaque>.mcp.sourcenerve.fogewise.io.vn`, which is outside the one-label wildcard and can fail the TLS handshake before traffic reaches the tunnel.

Do not put the real Cloudflare token into tracked config, Desktop resources, CI logs, support bundles, or renderer state.

The SourceNerve server must also have its normal OAuth issuer/resource configuration because broker authentication deliberately reuses the existing OAuth validation runtime.

## Cloudflare credential scope

The server credential must be scoped only to the Cloudflare account/zone used for SourceNerve Desktop routing and only to the tunnel/DNS operations required by this broker. Release/fork/PR jobs do not receive it.

The broker client uses only these Cloudflare operations:

- create/delete remotely managed tunnel;
- update tunnel secret;
- get tunnel run token;
- update tunnel configuration;
- disconnect tunnel connections after rotation;
- create/delete proxied DNS record.

## Routing identity

The broker derives hostnames from a SHA-256 digest of `(Auth0 subject, installationId)`, then uses only an opaque prefix in DNS. User IDs and installation IDs are not exposed in hostnames.

Example shape:

```text
8b970da06cce467b64d03eab.fogewise.io.vn
```

This branch implements installation-scoped direct routing. It does **not** by itself solve how a future public Plugin Directory listing with one universal SourceNerve MCP URL selects among multiple Desktop installations. #66/#71 must either add an authenticated central routing gateway or explicitly define the mapping from the universal product endpoint to the correct active installation.

## Failure/rollback behavior

For a new enrollment:

- tunnel-create failure: no local assignment is written;
- config failure: tunnel deletion is attempted;
- DNS-create failure: tunnel deletion is attempted;
- token-fetch failure: DNS/tunnel cleanup is attempted;
- SQLite persistence failure: DNS/tunnel cleanup is attempted.

Cloudflare response bodies are never logged. Safe logs contain only operation context and HTTP status when available.

## Rate limiting

Enrollment, rotation, and revocation are bounded in-process per `(subject, installationId, operation)` to 10 mutations/hour. This prevents accidental retry storms in one broker process.

A production multi-instance broker should move this limiter to shared durable infrastructure before horizontally scaling the broker; the current limiter intentionally does not pretend to be distributed.

## Security notes

- Every route requires a SourceNerve OAuth access token with the read scope.
- Installation ownership is exact Auth0 subject equality.
- A caller querying another subject's installation receives `not_found` rather than owner metadata.
- Installation IDs and metadata are strictly bounded ASCII inputs.
- Cloudflare API responses are size bounded.
- Tunnel run tokens are returned only from enroll/rotate, never from status.
- Account API credentials are server-only.
- No raw secrets are written to broker logs.
- Tunnel rotation uses 32 bytes from the operating system random source.

## Deployment gate

Do not enable this runtime until all of the following exist:

1. a dedicated Cloudflare API token with the reviewed tunnel/DNS permissions and resource scope;
2. the DNS suffix is inside the configured Cloudflare zone and generated installation hosts are covered by the deployed edge certificate;
3. SourceNerve OAuth is healthy;
4. the Desktop Native Auth0 application from #65 exists;
5. #66/#71 choose the final public routing story for ChatGPT Plugin traffic.

Until then, keep `SOURCENERVE_DESKTOP_BROKER_ENABLED` unset/false. The existing SourceNerve server and MCP behavior remain unchanged when the broker is disabled.

# Managed embeddings

SourceNerve can optionally generate OpenAI embeddings for indexed repository source and for text semantic queries. This layer is additive: Git, indexed file memory, the deterministic graph, SCIP enrichment, and the existing semantic-run validity rules remain authoritative.

Managed embeddings do not add an LLM planner, chat/completions execution, autonomous source mutation, or autonomous merge behavior.

## Enable the provider

Managed embeddings are disabled unless the server process has an API key:

```bash
export SOURCENERVE_OPENAI_API_KEY='<server-side key>'
# Optional. Defaults to text-embedding-3-small.
export SOURCENERVE_OPENAI_EMBEDDING_MODEL='text-embedding-3-small'
```

Production requests use the fixed OpenAI embeddings endpoint:

```text
https://api.openai.com/v1/embeddings
```

Clients cannot supply a provider URL. `SOURCENERVE_OPENAI_EMBEDDING_URL` exists only for controlled CI/testing and is accepted only when `SOURCENERVE_OPENAI_EMBEDDING_ALLOW_INSECURE_LOOPBACK=true`; the override must use a literal `http://127.0.0.1:<port>` URL.

The API key is environment-only. SourceNerve does not persist or return it, and the provider transport sends the Authorization header through process stdin rather than command-line arguments.

## Explicit data-egress boundary

Source code leaves SourceNerve only after an authenticated caller explicitly invokes managed indexing:

- REST: `POST /api/v1/semantic/provider/index`
- MCP: `semantic_provider_index`

Query text leaves SourceNerve only after an authenticated caller explicitly invokes:

- REST: `POST /api/v1/semantic/search-text`
- MCP: `semantic_search_text`
- `context_pack` with `provider_semantic: true`

Normal indexing, semantic vector import/search, architecture queries, and context packs with `provider_semantic` omitted or `false` do not call OpenAI.

## Managed indexing

Example request:

```json
{
  "workspace": "example",
  "client_run_id": "release-2026-08-18",
  "max_chunks": 128
}
```

The workspace must be clean and repository intelligence must be indexed at the current Git HEAD. SourceNerve creates a deterministic chunk plan from indexed UTF-8 source:

- files are processed in repository-relative path order;
- chunks are bounded by fixed line and byte limits;
- each chunk carries its exact current file SHA-256;
- binary/unindexed content is never sent;
- the request has bounded chunk count and total source bytes.

Embeddings are requested in bounded batches. Provider indexes may arrive out of order; SourceNerve normalizes them by the returned index and rejects duplicate, missing, or out-of-range indexes. Empty, non-finite, zero-norm, inconsistent-dimension, and oversized vectors fail closed.

Only after every provider batch succeeds does SourceNerve call the existing semantic import path. That final import rechecks the current Git HEAD, graph version, file SHA-256 values, ranges, dimensions, and vector validity transactionally. If repository state changed during the network calls, the generated vectors are not activated.

## Replay behavior

`client_run_id` is stable within a workspace. Before making a provider request, SourceNerve checks whether that ID already refers to a managed run for the same provider, model, HEAD, graph version, and exact chunk plan.

- identical replay returns the existing semantic run and performs no provider call;
- changed provider/model/repository state fails closed;
- a changed chunk plan under the same ID fails closed.

Provider/network failure therefore does not supersede the previously active semantic run.

## Text semantic search

Example:

```json
{
  "workspace": "example",
  "query": "billing reconciliation",
  "limit": 20
}
```

`semantic_search_text` requires a current active semantic run generated by the configured managed OpenAI model. SourceNerve embeds the query once, validates its dimension against that current run, verifies that the run did not change while the provider call was in flight, and then uses the existing exact cosine search.

The query text and query vector are not persisted.

## Context packs

Existing context behavior is unchanged by default:

```json
{
  "workspace": "example",
  "query": "billing reconciliation",
  "provider_semantic": false
}
```

To explicitly request managed query embedding:

```json
{
  "workspace": "example",
  "query": "billing reconciliation",
  "provider_semantic": true
}
```

The generated vector feeds the existing semantic ranking path, so selected items carry the same `semantic-vector` ranking reason and remain subject to the existing byte/item budgets. Architecture `seed_cluster_keys` may be used at the same time.

A request cannot provide both an explicit `query_vector` and `provider_semantic: true`; that ambiguous input fails closed.

## Failure and privacy contract

Managed provider calls use bounded connection/request timeouts and bounded response size. Redirect following is not enabled. Provider response bodies are not persisted in audit/task/status metadata, and SourceNerve returns sanitized provider transport/status failures instead of raw provider content.

Temporary request bodies are created with restrictive permissions on Unix and removed after the provider operation. They contain only the bounded source/query payload required by the explicit request.

SourceNerve never stores the OpenAI API key, raw Authorization header, provider response body, or query vector in semantic run metadata.

## Scope boundary

This capability intentionally does not include:

- OpenAI Responses or Chat Completions execution;
- server-side agent planning/orchestration;
- autonomous patch creation, merge, or shell execution;
- arbitrary OpenAI-compatible production endpoints;
- ANN/HNSW or an external vector database;
- distributed multi-writer coordination.
